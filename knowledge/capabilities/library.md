# Music library and playback

When a download finishes, lofty reads the incomplete file. An artist, album, or title tag moves it to `download_dir/Artist/Album/NN Title.ext`. A missing artist is `Unknown Artist`. A missing album is `Unknown Album`. A missing title keeps the file name. The track number is two digits. Characters that cannot sit in a path become spaces. A path that is already taken gains ` (2)`. A file with no tags, and a file that is not audio, stays on the Soulseek folder path, so an album download still lands in that album's folder.

After that filing, the music folder is swept. Images and other non-audio files under the download folder are removed, including a cover sitting beside a song and a nested scan image in the old album folder. A directory that no longer holds audio is removed. The download folder itself stays. Songs stay. The incomplete folder is left alone when it sits inside the download folder. The same sweep runs again when the library is checked. Removed files are dropped from the share index.

Filing uses the album artist. An AlbumArtist tag wins over the track artist. Guest wording is removed from that credit before the folder is chosen: `featuring`, `feat.`, `feat`, `ft.`, `ft`, `with`, `w/`, `w.`, `w`, `f/`, `f.`, `f`, `vs.`, `vs`, and `versus`. `Anthony Green feat. Prentiss` is filed under `Anthony Green`. `Drake with X`, `Drake f/ X`, `Drake f X`, `Drake w/ X`, and `Drake w X` are filed under `Drake` even when no other track on the album is tagged `Drake`. `ELla Langley feat.Miranda Lambert` is the same kind of credit. `Avalon (feat. Someone)` and `Avalon (with Someone)` are the album `Avalon`. `Simon & Garfunkel` stays one artist, and a track tagged `Simon` on that album joins it. `Coheed and Cambria` stays when `Coheed` is not already an artist on another album. `Green Day` and `Radiohead` on one album title stay two artists. The song title is left as tagged. The resolved artist is written into the artist tag and the album-artist tag. A later library scan renames a file that still sits in a guest folder, and the share index follows the new path.

A credit that extends an artist who already has a different album rolls under that artist. `Nine Inch Nails & David Bowie` and `Nine Inch Nails and David Bowie` are `Nine Inch Nails` when `Nine Inch Nails` already has another album. `and`, `&`, `+`, and `x` are that kind of extension, along with the guest wording above. A quality replacement keeps the original song's artist, album, title, and track. The replacement file's tags cannot open a second artist folder.

Artist and album names that differ only by case, or by an apostrophe or dash that looks like another, are filed and listed as one name. `Jack's Mannequin` and `Jack’s Mannequin` are one artist. The spelling already used by the most files wins. A tie keeps the spelling with more lowercase letters (`Hail the Sun` rather than `Hail The Sun`), and then the spelling with more ASCII characters. A mixed-case name capitalizes a fully lowercase word, so `Nine inch Nails` is `Nine Inch Nails`. A small word in the middle stays lowercase, and a single letter such as `x` stays as written. When every copy is all capitals or all lowercase, the written form is title case with small words left lowercase. A name with only one spelling is not otherwise restyled, so a lone `RADIOHEAD` stays. The chosen artist and album are written back into tags that already had those fields when a file arrives, when its bytes change, or when the chosen spelling changes. A file that is already cached is left on disk until the chosen name changes. A new download adopts that spelling and is filed in the matching folder.

When the file does move, that new path replaces the old one in the share index. Peers browse and search the new virtual path, uploads read the new disk path, and `SharedFoldersFiles` is sent again. A download folder that was not already under a share root is added to the public shares and saved in the account file. A file already under a buddy or trusted root stays at that level. An excluded name is removed from the index and is not advertised.

Key `0` opens the library. The spectrum meter is the top left. The track panel on the top right lists the title, artist, album, file type, bitrate, sample rate, bit depth, channel count, length, and file size. Artists are the left column, that artist's albums the middle, and that album's songs the right. `[` and `]` change column. `j` and `k` move inside the column. Enter plays the highlighted song. A click on a song plays that song. A click on an artist or album only changes the selection. Space pauses or resumes. `x` asks before deleting the highlighted artist, album, or song. Enter removes those files from disk. Esc leaves them. A song that was playing stops. The share index drops the deleted paths. Key `0` switches to the playback screen immediately. A catalog saved beside the account file, `library.toml`, is on screen at startup. The download folder is then checked on the library thread: a song whose size and modification time are unchanged is not read again. Its saved names stay unless the library's chosen artist or album differs, and tags are read only for a file that arrived, left, or was rewritten. That check starts when the account is loaded. With no saved catalog, folder names are listed before tags are read, so the terminal is drawn before the music folder is walked. A delete removes its rows at once, even while that check is still running. A finished download starts the same kind of check. Filing the finished file — reading tags, choosing the artist folder, and renaming — runs on a thread named `move`, off the runtime that reports transfer progress. The library check after that finish also runs beside the UI, whether or not a song is playing, and the list updates when it finishes. The download meter keeps its 200 ms tick, and a playing meter keeps drawing on the playback frame.

After that library check is applied, up to two threads named `quality` measure songs that have no saved verdict for the current size and modification time. The file that is playing is skipped and tried on a later pass. Each file is decoded at eight positions. The lossy percent is how much of the container's Nyquist range has no energy. A file is truly lossless only when the container is lossless and that percent is 10 or less. The bit depth, sample rate, percent, and verdict are saved on the catalog in `library.toml`. They are not written into the audio file, so the modification time stays put. The track panel adds one line when a verdict is saved: `lossless · N% lossy`, `lossy · N%`, or `not measured`. While nothing is playing, the `nothing playing` line stays, and the highlighted song's line is appended.

A truly lossless file at 24-bit or higher is kept. A truly lossless file below 24-bit gets one Soulseek search for a 24-bit replacement. A file that is not truly lossless gets one search for a lossless replacement. That search prefers 24-bit, then a hit that reports a sample rate, then the higher rate. The path must contain the artist and the title as whole words in that order, so `Air` does not match `Airborne` and `Song` does not match `Songbird`. The duration must be within 3 seconds when both sides report one. The search uses its own token for 8 seconds or 40 hits and does not replace the interactive search list. Sample rate on a hit is file attribute 4. Replacements download together when they come from different users. A user who is already sending one is skipped until that transfer finishes or fails, and the song waits instead of being forgotten. A peer who answers `Too many files`, `Too many megabytes`, `Internal error`, or `recent transfer failed` is skipped as well, and the next saved hit is downloaded. `recent transfer failed` is shown as `Last try failed`. The attempt is remembered only when no other eligible copy remains. Each file lands in `incomplete_dir/quality/` and is not filed while it is incomplete. After it finishes, the same measurement runs. A lossy original accepts any truly lossless file. A truly lossless file below 24-bit accepts only a truly lossless file of at least 24-bit whose measured range is at least as high. On acceptance the replacement keeps the original song's artist, album, title, and track, and is filed under that `Artist/Album`. The new file's tags do not open another artist. Then the original is deleted and dropped from the share index. A rejected download is deleted and the original stays. An empty search is remembered for that file's stamp. If the session is not signed in, the verdict is still saved and the search waits. Key `a` opens that work on its own view. Key `r` on that view forgets every saved verdict, writes `library.toml`, and measures the library again. The notice is `rechecking quality`. A measurement already running is discarded, and a library scan that started earlier cannot put the old verdicts back. `r` on any other view leaves the saved verdicts in place. The columns are measuring and replacing. Measuring lists songs that have no verdict yet. Replacing lists each song that still needs a better copy: `needs a lossless copy` or `needs a 24-bit copy`. When a replacement is downloading, that row names the advertised quality when the peer sent it, and the transfer state. The highlighted row shows the library file's verdict and, for the download, the user and remote file name. Search hits are not listed. Several replacements download at once, and each user sends only one. An empty column says `idle`. The screen is drawn from a cache rebuilt when a measurement or replacement changes, and `library.toml` is written when a measurement batch finishes. The search does not replace the interactive search list.

The hint under the tabs lists the keys: enter plays, space pauses, `s` stops, and `x` deletes. The log is not drawn on this view. Its place is two rows: a seek bar, then one row of icon-sized marks centered under it, `▶` `❚❚` `■`. The mark that matches the current state is highlighted. Clicking the triangle starts or resumes the song. Clicking the bars pauses it. Clicking the square returns to the start and stops. Dragging the bar, or clicking a column on it, moves the playhead to that fraction of the song. Adjacent columns land on different samples. The clock shows minutes, seconds, and hundredths.

Playback decodes with symphonia and writes f32 samples to the default output device through cpal. Sound starts once about a fifth of a second is decoded (and at least one spectrum window), and the rest of the file decodes while it plays. The output stream stays open until playback stops. The length comes from the container's frame count when that is known, so the seek bar does not wait for the whole file. While a song is playing the screen redraws about every 33 ms, and a song with no output device advances by that elapsed time. Transfer rates and idle time still update on the 200 ms tick. The meter uses the same braille density as the download chart and eases toward the next frame, rising faster than it falls. A quiet frame stays below the recent peak, so it does not stretch to the top of the cell. Low frequencies are on the left. Color runs from green, through amber, to red.
