# Server login session

`main` loads `Config` and builds one multi-thread Tokio runtime only when `username` is non-empty. `Session::spawn` dials `server_host:server_port`, writes `ClientMessage::Login` (major 177, minor 1), and reads one server frame with `FrameDecoder`. The whole connect, write, and read uses a 10 second deadline.

After `LoggedIn`, the task binds exactly `listen_port` (default 2234) on `bind_address`, or on every IPv4 interface when that address is empty. It then writes `SetWaitPort` and `SetStatus` online, and emits `Listening { port, address }`. `address` is the bound interface when `bind_address` is a specific IP. When `bind_address` is empty, `address` is the local address of the connection to the server. The listener accepts peer handshakes. A bind error emits `ListenFailed` and does not write `SetWaitPort`.

`Session::connect_peer` sends `GetPeerAddress`. A non-zero port is dialed and `PeerInit` is written (`P`, `F`, or `D`). A refused connect, or port 0, sends `ConnectToPeer` with a token and waits for `PierceFireWall` on the listen socket. An inbound `PeerInit` is the other direction. An inbound `ConnectToPeer` is answered by dialing that address and writing `PierceFireWall`. A refused dial sends `CantConnectToPeer` and does not emit `PeerFailed` or change a download row. A received `CantConnectToPeer` for a token this client is waiting on releases that wait, and a peer download still queued for that user becomes `Connection closed`. The same socket is then read. A `FileSearchResponse` there, for a token this client opened, becomes `SearchResult`. A file (`F`) socket is not parsed as peer frames. After this client writes `PierceFireWall` on an outbound `F` socket, it reads the 4-byte token and the file bytes. An inbound `PierceFireWall` of type `F` that matches a waiting upload writes the token and sends the file. At most 100 peer sockets are in flight; a full table emits `PeerFailed` and does not send `GetPeerAddress`. When a peer socket closes, that connection's slot is released. A finished or closed file socket releases its slot too, and so does a distributed socket when its read ends. An address lookup or indirect connect that is still waiting after 10 seconds is dropped and its slot is freed before the cap is treated as full. A slot that was already free is not released twice. A download still queued for that user asks for the address again. A later `FileSearchResponse` on a direct `PeerInit` whose token is still open also becomes `SearchResult`.

`Session::folder` sends `FolderContentsRequest` (peer code 36) on an existing peer writer, or after `GetPeerAddress` and `PeerInit`. The reply is `Folder` with one hit per file, path `directory\name`. It does not replace the browse list.

`Session::search` sends the mode's server message and emits `SearchBegan` with that token. A new search closes the previous interactive token. Wishlist tokens stay open. Wishlist mode does not send from `Session::search`; the task sends one configured wishlist query only after `WishlistInterval`. An incoming `FileSearch` is answered from the share index when the query is long enough and a filename token matches. The answer is a `FileSearchResponse` written after `GetPeerAddress` for the searcher. A one-character query sends nothing.

`Session::download` sends `QueueUpload` on an open peer writer, or asks for the address and writes `PeerInit` `P` first. A writer whose socket has already closed is dropped, and the download asks for a new address. An upload `TransferRequest` for that path is accepted with the incomplete file's current length as the offset. A path that uses `/` matches a queued path that uses `\`. An offered size of 0 keeps the size from the download request. The uploader's `F` socket sends the token, whether the uploader connected to the listen port or the server sent `ConnectToPeer` type `F` and this client dialed it. The client writes the offset and appends bytes under `incomplete_dir`, then moves the file to `download_dir` when the length matches. While bytes are still arriving, about every 200 ms, the row is updated with the bytes stored so far and the bytes per second over that interval. The finished report clears that speed. After `QueueUpload` the client sends `PlaceInQueueRequest`. A place of 4 stays on that row. A peer that cannot be reached changes the row to `Connection timeout`, `Connection closed`, or `User logged off`. Every three minutes, connection timeout and connection closed return to `Queued` and `QueueUpload` is sent again. Bytes already stored stay, so the next offer resumes at that offset. `User logged off` stays. When every file of one album download is connection closed, those rows become `Failed`, the incomplete file and any partial destination file are removed, and a global search for that album name starts. Results are collected for five seconds. The other peer with a free upload slot and the highest reported upload speed is then queued, and `FolderContentsRequest` asks for the rest of that folder. The peer that just failed is skipped. A busy peer is skipped even when their reported speed is higher. If nobody has a free slot, those rows say `Failed - Unavailable` and nothing is queued. A `Failed` row is not returned to the queue and is not asked again after restart. One file that is still transferring, or a download that was not part of an album, stays `Connection closed` and still retries. The file socket is read off the session task and matched after the offer is accepted. A folder download keeps that folder's own name, so `music\Dookie\01.flac` finishes at `download_dir/Dookie/01.flac`. A single file stays directly in `download_dir`. A folder name of `..` stays inside `download_dir`. A file socket that closes before the token, or a token with no waiting download, emits `PeerFailed`. A close before that length emits `Transfer` with `ConnectionClosed` and the bytes already stored. The next attempt sends that length as the offset. `Session::cancel` removes that user and path. `queue.toml` beside the account file is loaded after login. Finished rows stay finished. A download that was queued, transferring, paused, connection closed, connection timeout, or user logged off is asked again, and bytes already in the incomplete file stay. A peer `UploadDenied` sets the row from that reason: `Banned`, `Too many files`, `Too many megabytes`, `Pending shutdown`, `File not shared`, or `Cancelled`. Reason `Filtered` is shown as `Blocked by filter`, because that peer's filter rejected the file. A reason that starts with `Enqueue failed due to` keeps only the cause, so `Enqueue failed due to too many files` is `Too many files` and `Enqueue failed due to too many megabytes` is `Too many megabytes`. The downloads state column is 22 characters, and the longer sentence was cut off after `due to`. An unrecognized cause is shown without that prefix. Any other reason is shown as the peer wrote it. Cancelled rows, and the other refusal rows, stay as they were and are not asked. `File not shared`, `Too many files`, `Too many megabytes`, and `Internal error` become `Failed`, the partial file is removed, and a search queues that filename from the fastest other peer with a free slot. `Enqueue failed due to an internal error` is the same refusal. `Enqueue failed due to recent transfer failed` is shown as `Last try failed`: that peer will not queue the file because a transfer with them just failed, and a search queues the filename from another peer. A quality replacement does not start that search; it downloads the next saved hit from another user. If nobody has a free slot, the row says `Failed - Unavailable`. `X` on Downloads drops finished downloads, on Uploads drops finished uploads, and on the dashboard drops both. The file is written when a row is added, finished, refused, or removed, and when the session task stops. A queued upload that has not started a file connection is answered with `UploadDenied` reason `Cancelled`, and the next waiting upload can start. A download that is already gone answers a later `TransferRequest` with `TransferResponse` allowed false and reason `Cancelled`. Removing a row does not emit `Transfer` for that row.

An inbound `QueueUpload` is denied with `UploadDenied` when the username is banned, the path is not shared, the file count would pass `queue_file_limit`, or the queued bytes would pass `queue_megabytes`. Otherwise it waits. While fewer than `upload_slots` uploads are transferring, one starts with `TransferRequest`. A waiting upload gets `PlaceInQueueResponse`. A prioritized buddy is started before an earlier normal user. Privileged is stored from `GetUserStatus`. Default `upload_slots` is 2. `upload_limit_kib` and `download_limit_kib` pace a chunk when set; the delay for 1024 bytes at 1 KiB/s is one second. No fixture sleeps under a limit. After `LoggedIn`, dashboard meters use transfer byte deltas. The preview feed still uses `rate_at`.

After presence, the task sends `WatchUser` for each buddy. The reply and later `GetUserStatus` messages update that user's online, away, or offline state. `Session::browse` sends `GetPeerAddress` when needed, then `SharedFileListRequest` and `UserInfoRequest` on the peer socket. The share-list reply becomes one `BrowseRow` per file. The user-info reply fills the users detail pane. `Session::set_lists` replaces the ban, ignore, and priority sets. A banned username's search hit is dropped, and their `QueueUpload` is answered with `UploadDenied` reason `Banned`. An ignored username's upload is answered with `Cancelled`.

After the buddy watches, each `auto_join` room is sent as `JoinRoom`. An empty list sends nothing. `Session::say` writes `SayChatroom` after censor and word replacement. `Session::join` writes `JoinRoom`. `Session::set_away` writes `SetStatus` away or online. An incoming private message is always answered with `MessageAcked`. The configured auto-reply is sent as `MessageUser` only when that away flag is set and the reply string is non-empty. A room line is appended to `room_log_dir` when `log_rooms` is set and the directory is non-empty. `auto_away_minutes` of 0 does not change status from the UI idle clock.

When `upnp` is true and the listen socket bound, a task maps `listen_port`. An empty `upnp_gateway` uses the default route for NAT-PMP and, if that map fails or the route table has no default gateway, tries UPnP. A `host:port` value sends NAT-PMP only to that endpoint. The granted lifetime is renewed at half. A mapping failure emits `PortMapFailed` and the server read loop keeps going. `port_map_failure_keeps_the_server_connection` checks that a later `Relogged` is still `Kicked`.

After the listen socket is up, the task scans the share folders and emits `Shares` with the file and folder counts for public, buddy, and trusted. It then sends `SharedFoldersFiles` (server code 35): the public folder count, then the public file count. A successful `Session::rescan` replaces the index used for uploads and search replies, emits `Shares`, and sends code 35 again. A failed rescan emits `ShareScanFailed`, keeps the previous index, and does not send a new count. A finished download whose path changed does the same update without waiting for a rescan: the new file replaces the old path, `Shares` is emitted, and code 35 is sent again. When the download folder was not a share root, `ShareRoot` carries that folder. The UI appends it to the public share list, saves the config, and queues a rescan. `a_moved_download_is_indexed_and_advertised` starts with no public files, files a tagged wav at `library/Green Day/Dookie/01 Basket Case.wav`, and checks code 35 for one folder and one file, a browse of `library\Green Day\Dookie`, a `TransferRequest` for `library\Green Day\Dookie\01 Basket Case.wav`, and `UploadDenied` (`File not shared.`) for `library\01.wav`. `share_scan_reports_one_public_file` checks a folder that contains `note.txt`. `adding_a_share_folder_rescans_that_directory` starts with no public files, then a rescan of a folder that holds `note.txt` reports one public file. A peer `SharedFileListRequest` is answered from that index. A stranger sees `note.txt` and does not see a buddy-only `secret.txt` in the visible list. Buddy `carol` sees both. That browse also emits `Log` with `User bob is browsing your list of shared files`. An incoming search that returns files emits `Log` with `User bob is searching for "notes", found 1 results`. `a_public_share_is_announced_and_a_buddy_file_stays_hidden` checks the server counts, that browse, the log line, user info, and folder contents.

The task then reads server frames until shutdown. `GetUserStatus` (username, status `u32`, privileged bool) becomes `UserStatus`. `Relogged` (code 41, empty payload) emits `Kicked` and stops the task. Unrecognized server codes are ignored. A `Ping` is written only after 60 seconds with no other write.

| Event | When |
|-------|------|
| `LoggedIn { banner, ip, supporter }` | Success bool, banner, IPv4, digest, supporter bool. |
| `LoginFailed { reason }` | Success bool is false. The reason is also copied to the hints notice. |
| `Listening { port, address }` | The listen socket is bound and both presence messages were written. `address` is the interface in use. |
| `ListenFailed { message }` | The listen socket could not bind. The notice shows the message. The login banner stays. |
| `UserStatus { user, status, privileged }` | The server sent `GetUserStatus`. |
| `Kicked` | The server sent `Relogged`. The header becomes `logged in elsewhere`. |
| `TimedOut` | The login deadline passes, including a peer that accepts and sends nothing. |
| `Disconnected { message }` | The server socket closed, or the first write to it failed (including `Broken pipe (os error 32)`). The message ends with `reconnecting`. The login banner stays, file transfers stay up, and the client dials the server again. Later server writes wait for that new socket, so one close does not become a series of broken pipes. A listen-socket error uses the same message and does not end the session. |
| `SearchResult(token, hit)` | A peer `FileSearchResponse` matched an open token. The results list keeps it only when `token` is the current search. |
| `Folder { user, directory, files }` | A peer answered `FolderContentsRequest`. Each file path is `directory\name`. The browse list is unchanged. |
| `ShareScanFailed { message }` | The share walk failed, or a search or download was rejected before a server write. |
| `Transfer` | A download or upload changed state. Preview queue rows stay. |
| `Browse { user, rows }` | A share list reply. Preview browse rows stay, and these rows are appended. |
| `UserInfo` | A peer answered `UserInfoRequest`. The users detail pane shows the description. |
| `Watched { user, status, country }` | A `WatchUser` reply. |
| `Chat(ChatLine)` | A room line or a private message, after censor. Preview lines stay. |
| `RoomMembers { room, members }` | A join reply, a user entering or leaving, or the other party of a private message. |
| `RoomListed { room, users }` | One public room from `RoomList`. No fixture delivered a room list. |
| `Ticker { room, text }` | A room ticker. No fixture delivered one, so the drawn ticker stays `ticker · —`. |
| `PortMapped { external }` | NAT-PMP or UPnP published the listen port. The notice shows the external port. |
| `PortMapFailed { message }` | The map failed. The login banner stays. |
| `Shares { .. }` | The local share scan finished, or a moved download changed the index. The shares view shows those counts after login. |
| `ShareRoot { path }` | A moved download made `path` a public share. The folder is saved and a rescan is queued. |

Dropping `Session` aborts the task and closes the server socket and the listen socket. The UI loop drains the channel and calls `App::apply_session`. An empty username never starts that task. `Listening` does not clear the login banner.
