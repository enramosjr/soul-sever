# Nicotine+ parity

Target client: Nicotine+ 3.3.11 (16 September 2026). Soul Sever should be able to do what that client does, drawn as a terminal rather than GTK. Tray icons, native file choosers, and desktop notifications need a terminal equivalent, not a literal port.

The implementation order is [plans/nicotine-parity.md](../../plans/nicotine-parity.md). Status values below mean **in this repository today**.

| Area | Nicotine+ behavior | Soul Sever status |
|------|--------------------|-------------------|
| Server login | Login, banner, supporter flag, failure reason | Localhost fixture returns `LoggedIn` (`hello`, `127.0.0.1`) or `LoginFailed` (`INVALIDPASS`). Header follows that event. No official-server run. |
| Listen port, away status, server ping | SetWaitPort, SetStatus, ServerPing | After login, binds the configured port, sends `SetWaitPort` and online `SetStatus`, and pings after 60 idle seconds. `SetStatus` away follows `auto_away_minutes` of UI idle, or `Session::set_away`. Zero minutes stays online. |
| File search | Global, room, buddy, user, wishlist; filters; history | Typing the query sends it on Enter. Wishlist waits for `WishlistInterval`, then one item. A `FileSearchResponse` after `PierceFireWall` is shown when its token is the current search, including a path that does not contain the query phrase. A new search closes the previous token, so a late reply from the earlier query is left off the list. Lossless extensions stay above lossy ones when the queue length matches. Search rows put albums above single songs, and a shorter upload queue comes first inside each of those groups. A free slot comes before a busy peer at the same queue length. `.m4a` with a bit depth stays with the lossless rows. Files that share a directory collapse to one album until a click or Enter opens it. Dragging across results does not open or close it. `d` on that row queues the album and `FolderContentsRequest` fills in tracks in that directory; a file in another directory in the same reply is left off the list. The results title and the notice row keep `d downloads this album` or `d downloads this song` visible beside the result count. Quality, bitrate, duration, free slot, file type, size, country, include, and exclude filters hide rows. `]` cycles quality. A click cycles the other numeric rows. Country, include, and exclude are typed. After login the sample catalog is gone. |
| Downloads and uploads | Queue, resume, slots, bandwidth, filters, remote files | A fixture upload of 65536 bytes matches, and a close at 1024 resumes at that offset. A `ConnectToPeer` type `F` after an accepted `TransferRequest` writes the file and finishes the download. A folder download of `music\Dookie\01.flac` finishes in `Dookie` under the download folder. A single file stays directly in that folder. A queued download keeps the peer's place number. A peer socket that closed after search is asked again, and the row leaves `Queued` when that peer offers the file. An offer path `music/tone.bin` matches a queued path `music\tone.bin`. When that peer cannot be reached, the row says `Connection timeout`, `Connection closed`, or `User logged off`. Every three minutes those first two rows are asked again and resume at the bytes already stored. `User logged off` stays. When every file of an album download is connection closed, those rows say `Failed`, their partial files are removed, and a search for that album queues the fastest other peer who has a free slot. If nobody has a free slot, those rows say `Failed - Unavailable`. When a download is `File not shared`, that row says `Failed`, its partial file is removed, and a search queues the same filename from the fastest other peer who has a free slot. If nobody has a free slot, that row says `Failed - Unavailable`. A `Failed` row is not asked again. Two upload slots run; a third waits. `Banned` is `UploadDenied`. A download the peer refuses shows that reason. `Filtered` is shown as `Blocked by filter`. Any other reason is shown as the peer wrote it. File-count and byte caps use the Nicotine+ reason strings in unit tests. After login the queue shows the rows saved in `queue.toml`, and downloads that were still in progress are asked again. `x` on Downloads, Uploads, or the dashboard removes the highlighted row. `X` clears finished rows on that view, or both lists on the dashboard. A waiting upload is `UploadDenied` with reason `Cancelled`. Dashboard meters follow transfer byte deltas reported while the file is still transferring. The speed column shows that interval. Settings edits upload slots, queue mode, KiB/s limits, incomplete and download folders, and the queue caps, and the running session uses the new values. |
| Browse and user info | Share tree, interests, similar users | A fixture share list of two files becomes two browse rows, and the user-info description is shown. After login the sample tree is gone. Interest and similar-user layouts match Nicotine+; no fixture delivered those server replies. |
| Chat | Public rooms, private rooms, private messages, tickers, logging, censor, auto-reply | Auto-join sends `JoinRoom`. A fixture line is censored. After login the sample transcript is gone. Typing shows the message under the room, and Enter sends `SayChatroom`. Enter or a click on a room sends `JoinRoom`. A click on a person in the room opens a card: browse files, add friend, ignore, or ban. Private messages are acked. Auto-reply is sent only while away. A room log is written when logging is on. Room list and private-room admin replies were not delivered by a fixture. |
| Users | Buddies, trusted, prioritized, ignored, banned, notes | `n`, `p`, and `t` save buddy flags. A trusted toggle survives `load`. Ignore and ban are saved, drop that user's search hits, and reject uploads. After login the list is the saved buddies, ignores, and bans. Watch reports online, away, and offline. |
| Shares | Public, buddy, trusted; rescan; audio metadata | Local index from the three folder lists. On the shares view, Enter opens a folder browser at the home directory. Enter opens a directory, `s` shares the folder you are in, and that folder is saved for the highlighted level and rescanned. `[` `]` mark a path and `x` removes it. A public response omits buddy and trusted files. After login the shares view shows the scanned file and folder counts. A folder with `note.txt` counts as one public file. After the scan the server is told that public folder count and public file count, and a peer browse receives the visible list. That browse is also a log line, `User bob is browsing your list of shared files`. |
| Network | UPnP, NAT-PMP, bind address, port check | `upnp` tries NAT-PMP, then UPnP, and renews the map. Failure is a notice and the server connection stays up. A NAT-PMP fixture recorded port 2234. SSDP discovery was not fixture-tested. The settings screen edits the server, ports, UPnP switch, and gateway. Bind address opens a popup of this machine's interfaces. `all interfaces` leaves it empty. Those save and ask for a restart. |
| Distributed search | Parent, children, branch root | `DistribSearch`, `DistribBranchLevel`, and `DistribBranchRoot` match the Nicotine+ frame. The dashboard still shows `parent none` and `0` children. No fixture covers a parent connection. |
| Interests, recommendations, wishlist interval | Server messages 51–57, 103–104, 110–112 | `WishlistSearch` and `WishlistInterval` are implemented. Interest, recommendation, and similar-user layouts match Nicotine+. No fixture delivered those replies. |
| Plugins | Python plugin API and `/help` commands | Not started. |
| Config and logs | `~/.config/nicotine`, chat logs, statistics | TOML file at `~/.config/soul-sever/config.toml`, mode `0600`. The account password is stored in the system keyring, not in that file. Every field is editable on the settings screen. A room log appends when `log_rooms` is set and `room_log_dir` is non-empty. Private logging uses the same switch and was not fixture-tested. |
| CLI | `--config`, `--bindip`, `--port`, `--rescan`, headless | Those flags parse. `--rescan` prints the in-memory file count and exits 0, or exits 1 when a folder is unreadable. `--headless` prints the login banner and exits 0. `--rescan` exits before a headless login. |
| Library and playback | Not a Nicotine+ 3.3.11 surface | A finished audio file with tags is moved to `Artist/Album/NN Title.ext` under the download folder. A featuring credit is dropped from the artist and album, including a credit tight against the period. A track on an album that already has one artist uses that artist. Artist and album names that differ only by case are one entry, and that spelling is written back into the tag. Key `0` lists artist, album, and song. `x` asks before deleting the highlighted item from disk. The meter is top left and the track details are top right. Enter or a click plays a song. The log is hidden. A seek bar and icon-sized play, pause, and stop marks sit in its place. A click starts playback after a short decode instead of waiting for the whole file. While a song plays, the meter redraws about every 33 ms. The meter is a braille spectrum, green through amber to red, and a quiet frame stays below full height. |

Peer sockets complete `PeerInit` in both directions. A refused direct connect sends `ConnectToPeer` and accepts `PierceFireWall`. A refused inbound pierce sends `CantConnectToPeer` and stays out of the log. At most 100 peer handshakes are in flight. A finished file returns its slot, and an address lookup older than 10 seconds is dropped so a later peer can connect. Share lists are encoded and filtered by the requester. The peer socket sends that list when a peer asks, and the server is told the public counts. An incoming `FileSearch` for a shared word is answered with `FileSearchResponse`. A file socket carries a token, an offset, and raw bytes. After login, sample rows are gone. A browse asks for the share list and user info, and both are answered. A stranger's list omits a buddy-only file. The bottom log records that browse, and `` ` `` collapses the log to its latest line. A logged-in room line is the transcript. An empty username opens the sign-in form, and a name that is not already registered creates a new Soulseek account, and the sign-in form says that in the title style on two lines. There is no offline catalog.
